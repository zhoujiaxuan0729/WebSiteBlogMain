模型路由 / 多模型调度 / DeepSeek 调用其他模型 —— 9 对象可用性调研

调研日期：2026-11-01。所有数字均附来源 URL；GitHub 主站被 robots 拦截，star 数取自第三方镜像站（标注观测日期）或官方文档/官网自述。

1. LiteLLM（BerriAI/litellm）

  1. 名称与形态定位：Python 库 + 开源 LLM 代理网关（Proxy Server）。许可：MIT（enterprise/ 目录为商业授权，其余 MIT）。来源：https://www.litellm.ai/about ；https://pypi.org/project/litellm/1.78.3/
  2. 实现方式：统一 OpenAI 兼容 API 网关——把 DeepSeek、OpenAI、Anthropic、Gemini 等 100+ provider 统一成一个 /v1 端点；支持按成本/复杂度做 cost-aware routing、fallback、负载均衡、tag 路由。“DeepSeek 调其他模型”= 在网关配置里把请求转发/降级到其他 provider。来源：https://docs.litellm.ai/docs/agent_resources
  3. 安装与运行环境：pip install litellm 或 Docker，纯 Python。云电脑/沙箱：可；Android Termux：可（pip 直装）。
  4. 质量信号：GitHub 约 62.3k stars / 12.8k forks / 1700+ contributors（官方文档自述，2026-10 观测）：https://docs.litellm.ai/docs/agent_resources ；PyPI 版本 1.78.3（2025-10-18 发布）：https://pypi.org/project/litellm/1.78.3/ ；维护方为 BerriAI 商业公司，迭代极活跃。
  5. 冷门度与实用性：不冷门，事实标准。上手成本低（一个 config.yaml + 一行 litellm --config），文档质量高；企业级 SSO/RBAC/审计需付费 license。已知点：路由规则是配置式静态路由，不像 RouteLLM 那样训练分类器；enterprise 功能与开源版分离。
  6. 一句话结论：要"DeepSeek 主模型后面挂一堆其他模型"最稳妥的通用网关首选，开箱即用、生态最大。

2. new-api（QuantumNous/new-api）＋ one-api（songquanpeng/one-api）

  1. 名称与形态定位：自托管 LLM API 中转/分发网关（Go 为主，前端 JS）。
    • new-api：AGPLv3 + 附加署名/原项目链接条款（带 UI 的修改版须保留署名）。来源：https://docs.newapi.ai/en/docs/guide/wiki/basic-concepts/project-introduction ；https://www.apiseven.com/one-api-vs-new-api
    • one-api：MIT + 必须保留页面署名与项目链接。来源：https://ossean.com/songquanpeng/one-api ；https://guthub.com/songquanpeng/one-api
  2. 实现方式：网关统一转发——把 OpenAI/Claude/Gemini/DeepSeek/豆包/通义等多 provider 接到一个 OpenAI 兼容端点；带 渠道（channel）权重路由 + 自动 fallback、token 计费、用户/令牌管理。“DeepSeek 调其他模型”= 在渠道里配多个上游，按权重/优先级轮询与故障转移。
  3. 安装与运行环境：Docker 一键部署或单 Go 二进制。云电脑：可（docker/二进制）；Termux：可（Go 静态 aarch64 二进制可直接跑，docker 不便）。
  4. 质量信号：
    • new-api：约 50.9k stars / 12.3k forks / 1.4k open issues（ossean 2026-10-29 观测，最近 push 2026-10-28）：https://ossean.com/QuantumNous/new-api ；v1.0 下一代前端已发布：https://doc.newapi.pro/en/wiki/changelog/
    • one-api：约 37.0k–37.3k stars / 6.8k forks（ross.abutalabs 2026-09-29 观测 37,040；aitools.coffee 2026-10 观测 37,261）：https://ross.abutalabs.com/products/one-api ；https://aitools.coffee/apis/llm-providers/one-api/
    • 维护者：new-api 由 QuantumNous 社区（lead maintainer Seefs），one-api 原作者 songquanpeng（JustSong）。
  5. 冷门度与实用性：中文圈 Token 中转站事实标准，文档以中文为主。上手成本中等（需配渠道 key + 用户令牌）；适合个人/小团队做"一个 key 聚合多家 + 计费"。已知点：new-api 是 one-api 的活跃分叉（one-api 更新明显放缓）；AGPLv3 对对外服务有源码开放义务。
  6. 一句话结论：要"自搭一个 DeepSeek 为主、可挂其他家的中转站/计费面板"选 new-api；只要最简 MIT 中转选 one-api。

3. OpenRouter（openrouter.ai）

  1. 名称与形态定位：托管 SaaS 的统一推理 API 聚合层（闭源，非自托管）。运营方 OpenRouter Inc.。来源：https://www.truefoundry.com/fr/blog/what-is-openrouter-a-technical-guide-to-what-happens-to-your-request ；https://hivebook.wiki/wiki/openrouter-unified-llm-api-gateway
  2. 实现方式：一个 key + 一个端点统一访问 500+ 模型 / 80+ provider；默认 价格路由（自动选同模型最便宜 provider）、可选延迟路由、provider 级自动 fallback；支持 BYOK。“DeepSeek 调其他模型”= 在同一次编排里通过一个 endpoint 切换/并列调用不同厂商模型。
  3. 安装与运行环境：无需本地安装，注册拿 API key 即用。云电脑/Termux：只是 HTTP 调用，任何能联网的环境都可。
  4. 质量信号：商业产品，非开源故无 GitHub star；官网自述 700T+ tokens、500+ 活跃模型：https://openrouter.ai/ 。计费：预充 credits，Standard 手续费 5.5%、Business 8%、Enterprise 合同价；BYOK 直连按 provider 价：https://openrouter.ai/pricing
  5. 冷门度与实用性：不冷门，是 agent 框架（DSPy/Vercel AI SDK/aider/LiteLLM）最常用的跨 provider 桥。上手成本极低（注册→拿 key→改 base_url）；缺点是数据经过第三方、不能私有部署、用量付费。
  6. 一句话结论：不想自己搭网关、要"一个 key 调遍 DeepSeek/GPT/Claude/Gemini 并自动比价降级"的最快路径。

4. RouteLLM（lm-sys/RouteLLM）

  1. 名称与形态定位：Python 开源本地路由框架。许可：Apache 2.0。维护方 LMSYS Org（UC Berkeley，Chatbot Arena 团队）。来源：https://www.lmsys.org/ ；https://pypi.org/project/routellm/0.1.0/
  2. 实现方式：智能路由决策——用在人类偏好数据上训练的二分类路由器，把请求分流到"强模型（贵）“或"弱模型（便宜）"；提供 OpenAI 兼容 server，单命令启动。官方称在 MT-Bench 上降本 85% 同时保持 95% 质量。来源：https://pypi.org/project/routellm/0.1.0/ ；论文 arXiv:2406.18665
  3. 安装与运行环境：pip install routellm 或 clone 仓库，Python。云电脑：可；Termux：可（Python，但若跑本地小模型分类器需注意资源）。
  4. 质量信号：GitHub 约 5.6k stars（LMSYS 官网项目页自述 2026-10）：https://www.lmsys.org/ ；第三方观测 4.2k stars / 330 forks（arXiv 2608.03036，2026-09）：https://arxiv.org/html/2608.03036 。关键风险：自 2024-08 后基本停更，多个第三方评测标注 “unmaintained since 2024-08” / “dormant since Aug 2024”：https://clawrouters.com/blog/best-open-source-llm-router ；https://www.thedeepfeed.ai/posts/2026-06-09-llm-router-three-products-one-name/
  5. 冷门度与实用性：学术味重、是"成本-质量路由"的开创性参考实现。上手成本中等（要配 strong/weak 两个后端 + 选路由器模型）；文档是博客+论文+README。已知缺陷：维护停滞，新模型（DeepSeek V4 等）未纳入默认路由表，需自行重训。
  6. 一句话结论：思路漂亮但仓库已休眠，适合学习路由原理或自行 fork 维护，不建议直接上生产。

5. deepseek-multi-agent-plugin

  1. 名称与形态定位：Python 库 + CLI + HTTP 服务 + MCP server（多智能体协作插件）。许可：MIT。作者 Li3NGa（单人维护）。来源：https://pypi.org/project/deepseek-multi-agent-plugin/
  2. 实现方式：多模型组队（主管-下属 / 辩论 / 共识）——在 YAML 里定义一支 agent 团队（后端可为 deepseek / openai 兼容 / http / cli / python 自定义），用 6 种内置策略（broadcast / sequential / debate / supervisor / consensus / relay）协同；supervisor 策略即主管分解任务、工人并行执行、主管汇总，天然就是"DeepSeek 主模型调其他 agent”。共享 MessageStore、按 agent 统计 token、带 Trace。来源同上。
  3. 安装与运行环境：pip install deepseek-multi-agent-plugin，零运行时依赖（仅标准库），Python ≥3.10；可选 Docker。云电脑：可；Termux：非常可（纯 Python 标准库，wheel 仅 49.6KB）。
  4. 质量信号：PyPI 最新 v1.0.1，发布于 2026-08-17（同日还有 1.0.0，仅 2 个版本）；Development Status 标注 “5 - Production/Stable”；1 个 maintainer；无 provenance（未走可信发布）。来源：https://pypi.org/project/deepseek-multi-agent-plugin/
  5. 冷门度与实用性：极冷门单人项目。上手成本低（--demo 用 mock agent 跑辩论无需 key），文档意外地全（docs/ 含策略详解/API/HTTP/MCP/部署）。已知缺陷：社区零、无第三方背书、刚发布两个月、作者单人，长期维护存疑。
  6. 一句话结论：想要"DeepSeek 当主管/裁判，组队调其他模型辩论投票"且零依赖秒装，可直接试；但要按个人玩具项目预期管理。

6. chimera-deliberation

  1. 名称与形态定位：Python 动态多模型 deliberation 网关（CLI + REST + Web UI + MCP）。许可：MIT。作者 Total Wind-Up Flight Systems（dev@totalwindup.com，单人 maintainer totalwindupflightsystems）。来源：https://pypi.org/project/chimera-deliberation/
  2. 实现方式：dispatcher-worker-aggregator 三段式——一次 API 调用里，dispatcher 模型（默认 deepseek/deepseek-v4-flash）先设计整张 DAG、给每个 worker 写定制子任务与合并指令；worker 并行调不同厂商 LLM（Claude Sonnet / DeepSeek / GLM 等）；aggregator 按 dispatcher 指令合并。底层复用 LiteLLM gateway。对外暴露 OpenAI 兼容 /v1/chat/completions + MCP 工具。来源同上。
  3. 安装与运行环境：pip install chimera-deliberation[full]，Python ≥3.11（依赖 fastapi/uvicorn 做 server）。云电脑：可；Termux：需 proot/装好 Python 3.11+，理论可但偏重。
  4. 质量信号：最新 v0.2.8，2026-10-25 发布；Development Status 3 - Alpha；2026-06-18 首发 0.1.0，到 10 月已迭代 9 个版本，活跃；1 maintainer，无 provenance。来源：https://pypi.org/project/chimera-deliberation/
  5. 冷门度与实用性：极冷门、单人 Alpha。上手成本偏高（要先 chimera config init 生成 chimera.yaml、配多家 API key、理解 formation/DAG 概念）；文档详尽（CONFIG/USAGE/INTEGRATION/SECURITY/RESILIENCE 等 9 篇）。已知缺陷：Alpha 阶段、配置项多、/v1/health 每次探测会真实消耗各 provider token。
  6. 一句话结论：“一次请求、一个 dispatcher 自动组队多模型再合并"的自动化程度最高，但处于 Alpha，适合愿意折腾 YAML 的进阶用户。

7. external-agents（@mrrlin-dev/external-agents）

  1. 名称与形态定位：Node.js MCP server（npm 包）。许可：MIT，出品方 Mrrlin（mrrlin.com，npm 账号 aiuxsolutions）。来源：https://www.npmjs.com/package/@mrrlin-dev/external-agents ；https://www.npmjs.com/~aiuxsolutions
  2. 实现方式：MCP 互调 + 配额池路由——把 Claude Code / Codex / Cursor 这类主 agent 接到一个 MCP server，由它把活 round-robin 派发给 20–40+ 廉价/免费模型桶（Gemini free、Groq、Cerebras、OpenRouter :free、Z.ai GLM、DeepSeek 便宜档）；按响应头 x-ratelimit-* 观测真实剩余配额，429 时按 provider 真实 reset 时间冷却后切换；也支持 pick_agents 从不同 provider 各挑一个做评审团。来源：https://www.npmjs.com/package/@mrrlin-dev/external-agents ；https://dev.to/elispeak111/how-i-turned-fragmented-llm-quotas-into-one-larger-token-budget-with-an-mcp-server-2ek1
  3. 安装与运行环境：npm i @mrrlin-dev/external-agents，Node.js。云电脑：可；Termux：可（Termux 自带 Node/npm 即可）。
  4. 质量信号：npm 最新 v0.63.0，约 12 天前发布（2026-10 中下旬）；累计 106 个版本，迭代非常勤；但 0 dependents、2 dependencies、Code Beta。来源：https://www.npmjs.com/package/@mrrlin-dev/external-agents
  5. 冷门度与实用性：冷门但作者主动写博文推广（DEV Community）。上手成本低（npm 装完在 Claude Code/Codex 里 claude mcp add）；核心卖点是把散落的免费配额拼成一个大池子、对抗前端编码 agent 的高额账单。已知缺陷：0 下游依赖、纯个人/小团队工具、“路由准不准"取决于各 free tier 稳定性。
  6. 一句话结论：如果你已经在用 Claude Code/Codex，想让它把杂活甩给 DeepSeek/免费模型省钱，这个 MCP 包最对口。

8. Dify（langgenius/dify）

  1. 名称与形态定位：开源 LLMOps / Agentic 工作流平台（Python 后端 + Next.js 前端）。许可：Dify Open Source License（Apache 2.0 修改版——允许商用，但未经授权不得做多租户托管服务）。来源：http://raw.githubusercontent.com/langgenius/dify/main/LICENSE ；https://aiwiki.ai/wiki/dify
  2. 实现方式：可视化工作流编排——在画布上拖节点，每个 LLM 节点可单独选不同 provider/模型（DeepSeek、GPT、Claude、本地模型等），配合条件分支、HTTP 节点、工具节点，实现"主流程用 DeepSeek、子任务路由到其他模型”。来源：https://dify.ai/
  3. 安装与运行环境：docker compose up -d 一键；技术栈 Python + Node + PostgreSQL/Redis/Weaviate。云电脑：可（需 2C4G 以上跑 docker）；Termux：不现实（依赖 docker 与多组件，不建议）。
  4. 质量信号：GitHub 约 159.9k stars / 25.3k forks（ghtrends 2026-10-29 观测，最近 commit 2026-10-29）：https://ghtrends.dev/langgenius/dify/ ；官网自述 148k+（2026-10）：https://dify.ai/ ；商业公司 langgenius 维护，迭代极活跃。
  5. 冷门度与实用性：不冷门，国内 LLMOps 头部。上手成本中等偏上（要装整套 docker 栈，但开箱有 Web UI）；文档中文友好、插件市场成熟。已知点：非纯 OSI（多租户限制）、重型、自托管资源占用不小。
  6. 一句话结论：要做"可视化拖拽把 DeepSeek 和其他模型/工具串成业务工作流"的产品级平台，选 Dify。

9. n8n（n8n-io/n8n）

  1. 名称与形态定位：fair-code 工作流自动化平台（TypeScript/Node.js）。许可：Sustainable Use License（source-available，非 OSI；可自托管内部使用，但不能作为托管服务转售）。运营方 n8n GmbH（柏林，2019 创立）。来源：https://n8n.io/press/ ；https://agents-oss.com/projects/n8n/
  2. 实现方式：通用工作流编排——400+ 集成节点 + 原生 AI Agent / LLM 节点；在工作流里串接不同 LLM provider 节点（含 OpenAI/DeepSeek/本地模型），用条件/合并节点实现 DeepSeek 与其他模型之间的路由、串联、人工审核。来源：https://n8n.io/
  3. 安装与运行环境：npx n8n / npm i -g n8n / Docker，Node.js。云电脑：可；Termux：可（Node 原生，npx n8n 可起，但重型工作流建议云电脑）。
  4. 质量信号：官网自述 约 209.1k stars（2026-11）：https://n8n.io/?lang=en ；累计融资 $240M（Accel/Sequoia/NVIDIA NVentures 等），250k+ 社区：https://n8n.io/press/
  5. 冷门度与实用性：不冷门，通用自动化头部。上手成本低（可视化、模板多）；文档全。已知点：非 OSI 许可限制转售；AI 路由能力偏"节点编排"而非"按 prompt 复杂度自动选模型”。
  6. 一句话结论：要把 DeepSeek 与其他模型/外部 SaaS 业务系统编排进自动化流水线，n8n 最成熟；纯"模型间智能路由"不是它的强项。
