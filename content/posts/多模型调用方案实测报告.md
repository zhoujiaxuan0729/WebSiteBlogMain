# 多方案实测:DeepSeek 自主调用其他模型(2026-10-31)

> 目标:验证"DeepSeek 主模型调用其他(免费)模型 + 被调模型能否联网搜索"的各类开源方案,对比配置流程/多平台兼容性/稳定性/易用性。
> 环境:云主机 Linux(node v? / python3.12 / dsh 0.2.1-rc.5),API key:智谱免费 + 魔塔免费。

## 结论速览

| # | 方案 | 类型 | 实测结果 | 一句话评价 |
|---|---|---|---|---|
| 1 | **dsh-model-call(自研)** | dsh 插件 | ✅ 端到端可用 | DeepSeek 自主调用智谱/魔塔,智谱免费模型可联网搜索;最贴需求 |
| 2 | dsh-set-model 0.3.1 | dsh 开源插件 | ❌ 启动冲突 | 与 dsh 0.2.1-rc.5 内核 prompt section 重名,无法加载 |

## 方案 1:dsh-model-call(自研,基准)

- **配置流程**:插件文件放 `~/.dsh/profiles/web/node_modules/dsh-model-call/`,在 `cordis.patch.yml` insert 挂载;key 存 `~/.dsh/.credentials.yaml` refs。
- **兼容性**:dsh web(Linux)已验证;纯 node 插件,机制跨平台(Windows/Termux 的 dsh 同样适用)。
- **稳定性**:✅ 高。多轮浏览器端到端验证:DeepSeek 自主触发 `call_model·zhipu` → 智谱返回 → DeepSeek 整理,稳定。
- **易用性**:✅ 对话里直接说"用智谱免费模型…"即可,DeepSeek 自主决定调用。
- **联网搜索**:✅ 智谱免费模型(glm-4.5-flash/glm-5.3-flash)原生支持 web_search 工具,已升级插件自动开启;curl 实测搜到"2026-10-31 武汉天气 25/16 多云"。魔塔不支持 web_search(报错 function required),但支持 function calling;DeepSeek 主模型可先搜索再转喂魔塔。
- **来源**:自研 `~/.dsh/profiles/web/node_modules/dsh-model-call/{index.js,package.json}`

## 方案 2:dsh-set-model 0.3.1(john-walks-slow)

- **配置流程**:`dsh plugin --profile web add github:john-walks-slow/dsh-set-model`;需先往 `pnpm-workspace.yaml` 的 `allowBuilds` 加 codeload key;再在 patch insert 挂载。
- **实测**:装好后 dsh web 启动即报 `Error: prompt section "dsh:model-policy" is already registered`(与 dsh 0.2.1-rc.5 内核/system-prompt 段重名),插件无法加载。
- **兼容性**:❌ 与当前 dsh 版本冲突(内核已注册同名 section)。
- **稳定性**:低(每次启动报错)。
- **易用性**:机制上是"agent 通过 set_model/list_models 工具自主切换 provider/model 预设"——最贴近"自主调用"语义,但当前版本不可用;需等插件适配新 dsh 或换旧版 dsh。
- **来源**:GitHub john-walks-slow/dsh-set-model;DSH Plugin Store @lwmxiaobei 收录。

## 方案 3:dsh-agent-conductor 0.3.1(Lionad-Morotar)

- **配置流程**:`dsh plugin --profile web add dsh-agent-conductor`(npm 名);git 方式安装会因 ssh 协议失败,需走 npm 包。
- **实测**:启动报 `tool "conductor_dispatch" is already registered`,工具无法注册;README 主推 **skill 形式**(复制 `skills/conductor` 目录,零依赖,模型按描述自动识别触发,stdout 直接成答案)。
- **兼容性**:❌ 工具注册冲突;skill 形式未实测(需复制目录进 skills)。
- **稳定性**:低(插件形式);skill 形式设计为 session-scoped、只读脚本,理论上更稳。
- **易用性**:调度 11 个外部 agent CLI(Codex/Claude Code/OpenCode/Gemini/Kimi/Qwen 等),**需要外部 CLI 已安装并登录**;与本场景(智谱/魔塔 API)不直接匹配。
- **来源**:GitHub Lionad-Morotar/dsh-agent-conductor(npm dsh-agent-conductor)。

## 方案 4:deepseek-multi-agent-plugin 1.0.1(PyPI)

- **配置流程**:`pip3 install deepseek-multi-agent-plugin`;代码里 `AgentCoordinator` + `Agent(name, provider, model, base_url, api_key)` + `register_agent`;策略函数 `run_broadcast / run_debate / run_relay / run_consensus` 等。
- **实测**:✅
  - 广播:DeepSeek + 智谱 glm-4.5-flash + 魔塔 Qwen3.5-27B **三模型并行**回答同一问题,全部正常。
  - 主管-下属:DeepSeek 先决策生成问题 → 智谱回答 → DeepSeek 总结,**真实"模型调用模型"链路全通**。
- **兼容性**:✅ 纯 Python 标准库 + OpenAI 兼容 HTTP,Linux/Windows/macOS/Termux(python3)均可;智谱/魔塔/DeepSeek 官方都走 `openai` provider(base_url 区别)。
- **稳定性**:✅ 高(标准 chat/completions,带重试/退避);无 UI。
- **易用性**:中——需写 Python 代码编排;有 6 种开箱策略 + 记忆/上下文策略。
- **来源**:https://pypi.org/project/deepseek-multi-agent-plugin/

## 方案 5:chimera-deliberation 0.2.9(PyPI)

- **配置流程**:`pip3 install chimera-deliberation`;pydantic `ChimeraConfig(providers/models/api_keys/defaults)` + `Engine(cfg, LiteLLMGateway(cfg))`;`await engine.deliberate(prompt)`(async)。
- **实测**:✅ Dispatcher(DeepSeek)自动设计 formation:3 个 worker(deepseek/智谱/魔塔)并行 + aggregator(DeepSeek)合并,输出最终一句话答案,含结构化 trace。
- **兼容性**:⚠️ 依赖 litellm;魔塔模型 id `Qwen/Qwen3.5-27B` 在 litellm 被截断成 `Qwen3.5-27B` 导致 BadRequest(降级继续,最终答案仍出);DeepSeek/智谱正常。平台纯 Python。
- **稳定性**:中——有 degraded 降级机制,但魔塔需要模型 id 别名处理。
- **易用性**:中——配置结构多(formations/Defaults/api_keys),async API。
- **来源**:https://pypi.org/project/chimera-deliberation/

## 方案 6:router-maestro 0.7.5(PyPI)

- **配置流程**:`pip3 install router-maestro`;写 `~/.config/router-maestro/providers.json`(provider: baseURL + api_key_env + models);export key 环境变量;`router-maestro server start --port 8099 --api-key xxx`。
- **实测**:✅ 网关启动(OpenAI 兼容 `http://127.0.0.1:8099/api/openai/v1`);经网关调用 **智谱 glm-4.5-flash、魔塔 Qwen3.5-27B、官方 deepseek-chat 全部转发成功**。
- **兼容性**:✅ 跨平台;任何 OpenAI 兼容客户端(Claude Code/opencode/curl)都能指到网关用任意模型;配套 `config claude-code/codex/gemini` 生成对应 CLI 配置。
- **稳定性**:✅ 高(标准 OpenAI API 转发)。
- **易用性**:✅ 高——配置一次、标准 API;**注意**:这是"统一网关/路由",不是"模型调用模型"(主模型仍需借助客户端/工具才能触发)。
- **来源**:https://pypi.org/project/router-maestro/;本地配置文件 `/home/user/.config/router-maestro/providers.json`,网关进程运行中(8099)。

## 方案 7:external-agents 0.63.0(npm, MCP)

- **配置流程**:`npx @mrrlin-dev/external-agents`;提供 `external-agents`(CLI)与 `external-agents-mcp`(MCP server)两个 bin。
- **实测**:`pick --n 5` 正常返回候选(gemini-3.6-flash、claude-sonnet-5、groq-gpt-oss-120b、openrouter-*、ollama-* 等 20+ 桶);`dispatch` 依赖外部 agent CLI(Codex/aider/agy 等)且需文件上下文,未完整跑通一条。
- **兼容性**:⚠️ node 跨平台;桶全部为 Groq/OpenRouter/Ollama/Claude/Codex/Gemini 系,**无智谱/魔塔/DeepSeek 桶**,与本场景不适配。
- **稳定性**:中——依赖各厂商登录态/key + 外部 CLI。
- **易用性**:中——面向 Claude Code/Codex 生态的 MCP/CLI,不是给 dsh 用的。
- **来源**:npm @mrrlin-dev/external-agents;https://lobehub.com/mcp/mrrlin-dev-external-agents

## 建议

1. **当前场景(dsh 对话里 DeepSeek 自主调用智谱/魔塔 + 联网)**:保留自研 dsh-model-call——唯一端到端可用、智谱免费模型可联网搜索、零额外依赖。
2. **想要框架级多模型编排(Python)**:deepseek-multi-agent-plugin 主管-下属最贴合;chimera 适合"自动编排 + 汇总"。
3. **想要统一网关给多个客户端用**:router-maestro(已在 8099 运行,可直接当 OpenAI 兼容端点用)。
4. **开源 dsh 插件**:dsh-set-model/conductor 与 dsh 0.2.1-rc.5 冲突,等上游适配;conductor 的 skill 形式可后续试。
