# 类 DSH 的 AI 开发/对话客户端横向对比（调研日：2026-11-01）

> 基准：dsh（DeepSeek Harness）本体 `@deepseek-ai/dsh` v0.2.1-rc.5（预发布）[1]；官方 npm 目录包 `dsh-plugin-catalog` 收录 4092 插件，仅 27.4% 标注 engines.dsh 版本要求 [2]；dshmk.com 收录 2500 插件、开发工具类占 56% [3]。安装 `dsh plugin add <spec>`，插件本质是 npm 包。
> 下文所有数字均附来源编号，见文末「来源索引」。

---

## 一、核心结论

1. **「像 dsh 的软件」本质分四类形态**：终端 CLI Agent（与 dsh 同类）、IDE 扩展（宿主是 VS Code）、自托管 Web UI、桌面客户端/AI IDE。dsh 属于第一类，插件生态数字（4092）虽大，但质量信号最弱——仅 27.4% 插件标注版本要求，兼容性风险高 [2]；真正生态成熟的是 claude code（官方 marketplace）[13]、openwebui（六类插件机制 + 数百社区工具）[33]、cursor（直接继承 VS Code 市场）[53]。
2. **CLI Agent 梯队**：claude code（15.3 万 star、Anthropic 官方、按日发版）> codex cli（13.1 万 star、OpenAI 官方、Rust 二进制）> aider（5.0 万 star、Apache-2.0、支持本地模型）> opencode（3.4 万 star、MIT、多模型接入）。claude code 与 codex 均为官方产品但模型绑定强（Claude 系 / OpenAI 系），aider 与 opencode 是「自带任意 Key + 本地模型」的自由派 [8][15][4][11]。
3. **许可自由度差异大**：MIT/Apache-2.0 全开放（opencode、aider、codex cli、cline、continue、librechat）；AGPL-3.0/GPL-3.0（cherry studio、chatbox）；**claude code 源码可见但非 OSI 开源**（npm 标注 "SEE LICENSE IN README.md"）[12]；openwebui（BSD-3 + 品牌条款）[31] 和 lobehub（Apache-2.0 + 衍生商用限制）[40] 的「开源」都有附加条件。
4. **对本地模型（Ollama）支持**：openwebui（本地模型优先）[33]、continue（Ollama 一等公民、AUTODETECT）[28]、cline（Ollama/LM Studio）[22]、aider（Ollama/llama）[10]、cherry studio（可完全离线）[45] 最友好；claude code / codex / cursor 基本绑定云端商业模型。
5. **维护风险提示**：aider 仅 1 个 PyPI maintainer（bus factor 高）[9]；continue 的 release tag 滞后主分支 4 个月 [29]；claude code open issues 15.7k、codex 24.3k（issue 洪流但官方维护密集）[11][15]；lobehub 的「30 万 Skills / 11 万 MCP」是官方营销口径、非仓库可验证数据 [42][43]。
6. **按你的场景（全栈 + 多模型调试 + Linux 云电脑/沙箱 + Termux + Windows）**：CLI 场景 dsh/opencode/aider 是主力（Termux 里跑 Node/Python CLI 最顺）；云电脑上 VS Code（code-server）装 cline/continue 承接 Agent 编程；自托管 Web UI 选 openwebui 管本地模型 + RAG；桌面端 cherry studio 是国产模型聚合最全的开源选项；cursor 性价比最低（订阅 $8/月起、闭源）[51]。
7. **「DeepSeek 调用其他模型」是独立的一层，不在客户端里**：此前调研确认编程工具（opencode/claude code）只支持手动切模型、无"主模型自主调其他模型"的原生能力，需要网关/路由/组队层补位。该层选型分四档：自建网关 **LiteLLM**（事实标准、Termux 可 pip）或 **new-api**（国内模型+计费、Go 静态二进制）；零部署用 **OpenRouter**（一个 key 聚合 500+ 模型）；"DeepSeek 当主管组队"最对口的是 **deepseek-multi-agent-plugin**（纯 Python 零依赖、49.6KB wheel）[65]；已在用 Claude Code/Codex 的省钱方案是 **external-agents**（MCP 配额池路由）[67]。**RouteLLM 已停更（2024-08 起休眠）不建议上生产** [64]。

## 六、模型路由 / 多模型调度层（「DeepSeek 调用其他模型」的冷门实用方案）

## 七、选择建议（按你的场景：全栈开发 + 多模型调试 + Linux 云电脑/沙箱 + Termux + Windows）

1. **Termux / 云电脑 SSH 无头环境（CLI 主力）**：继续用 dsh 盯 DeepSeek 官方生态；并行装 **opencode**（MIT、Node 生态、多模型）或 **aider**（Python、本地模型、自动 Git 提交）做多模型调试最顺手。claude code / codex 功能强但模型绑定重，适合你把 Claude/OpenAI 账号用起来时再上。
2. **云电脑的 VS Code（code-server）**：装 **cline**（自主 Agent + MCP，576 万安装量）或 **continue**（四合一 + Ollama 本地模型一等公民）。对全栈 + 多模型场景，continue 的 config.yaml 多 provider 更贴合「调试多家模型」的需求。
3. **自托管 Web UI（跑在云电脑/沙箱里长期开）**：首选 **openwebui**——本地模型优先、六类插件机制、RAG 和多用户；多 API key 聚合选 **librechat**（MIT 最宽松、被 ClickHouse 收购后仍在维护）。
4. **桌面端（Windows / 云电脑 GUI）**：**cherry studio** 是开源里国产模型聚合最全的（含 DeepSeek、支持离线 Ollama + MCP）；**chatbox** 胜在六端轻量。
5. **不建议优先**：**cursor**（闭源订阅，$8/月起，自带模型池限制多——Free/Plus 档不能接第三方模型/自带 Key [51]，与你要「多模型调试」的目标相悖）；lobehub 的生态数字虽大但属营销口径、许可对衍生商用有限制。
6. **「DeepSeek 调用其他模型」方案层**：自建网关选 **LiteLLM**（通用、Termux 可 pip）或 **new-api**（国内模型+计费、Go 静态二进制 Termux 可跑）；不想自建直接 **OpenRouter** 一个 key 聚合 500+ 模型。要「DeepSeek 当主管组队调其他模型」最对口的是 **deepseek-multi-agent-plugin**（纯 Python 零依赖，Termux 极轻，可先 `--demo` 跑通再配真实 key）[65]；已在用 Claude Code/Codex 想省钱选 **external-agents**（MCP 配额池）[67]。**RouteLLM 已停更，跳过** [64]；Dify/n8n 属于重型平台，仅当需要可视化业务工作流时再上。
